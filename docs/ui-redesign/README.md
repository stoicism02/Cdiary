## 已确认：保留现有任务便签

用户确认喜欢当前任务便签。A / B / C 均不改动其外观、窗口模式、直接编辑、失焦自动保存、置顶、自选背景与全局背景透明度。主窗口继续只读展示笔记，编辑仍打开现有任务便签。后续主窗口主题不得通过共享资源或编辑器 CSS 意外影响便签。

评审台的任务便签入口现展示现状截图。初稿中的三套便签效果图已作废，仅保留历史文件，不作为实施依据。

**先打开 [设计评审台](index.html)**：可切换三套方案及主要页面；“现状证据”展示当前 WPF 控件的真实渲染。方案中的按钮只操作内存中的示例数据，不连接业务数据库。

| 方向 | 核心组织方式 | 最适合 | 主要取舍 |
| --- | --- | --- | --- |
| [A 轻岛](01-direction-a.md) | 功能侧栏 + 清单 / 阅读双栏 | 每天安排任务、随手记笔记 | 最贴近现有习惯；风格变化比较克制 |
| [B 纸页](02-direction-b.md) | 日期索引 + 一张连续的日记录 | 经常回顾某天做了什么、写每日备忘 | 记录感最强；跨页面导航需要重新熟悉 |
| [C 专注台](03-direction-c.md) | 顶部工作区 + 紧凑任务表 + 侧边专注 | 长时间学习、编程、资料摘录 | 信息密度与专注最好；深色主题维护成本较高 |

建议优先选 **A**：它保留“小岛”的轻松感，同时能直接解决清单空间不足、主次操作混杂。若“每天的一页记录”更重要，选 B；若软件大部分时间伴随学习和计时，选 C。现有任务便签在三案中保持原样。
