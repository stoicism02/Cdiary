## 资源对比

同一个验收宿主分别加载改版前备份程序集与本次源码程序集，每个版本独立启动进程。均使用 100 个任务、每个任务 80 组 Markdown 小节；便签保持现有直接编辑模式，并等待真实 WebView2 就绪。没有启动托盘、全局截图快捷键或正式提醒调度，因此这些值是控件宿主的对照，不能冒充正式程序的完整资源开销。

内存单位为 **MiB**，采用宿主与其 WebView2 进程的专用内存之和；工作集可能重复计算共享页，所以没有将其作为主要指标。CPU 按本机 16 个逻辑处理器归一化，每阶段约采样 6 秒，窗口离屏且不激活。它是短时样本，不能证明长期闲置、可见桌面上的 GPU 表现或统计显著性。

| 场景 | 改版前专用内存 MiB | 改版后专用内存 MiB | 改版前整机 CPU | 改版后整机 CPU |
| --- | ---: | ---: | ---: | ---: |
| 主窗口显示（离屏） | 124.9 | 125.9 | 3.37% | 3.56% |
| 主窗口隐藏 | 115.0 | 114.9 | 0.16% | 0.19% |

本次样本没有显示明显的内存增加。多个便签的主要成本仍来自现有 WebView2 编辑器，三便签约 686 MiB，应作为后续性能优化重点，不能声称当前已达到极低内存。便签外观与编辑体验按照用户要求保留。

记录中的 `windowInitializationIncluding1000msSettle` 是构造并显示测试窗口到固定等待结束的时间，包含 1000 ms 稳定等待、不包含正式 App 冷启动和托盘初始化，不作为冷启动速度结论。主窗口显示、便签阶段的 CPU 也包含短时渲染影响，不是长时间后台 CPU。

原始数据：[布局](acceptance/acceptance-layout.json)、[改版前资源](acceptance/performance-before.json)、[改版后资源](acceptance/performance-after.json)。程序集 MVID 保存在资源记录中，改版前程序集来自此次改版发布前的本地备份；依赖与测试宿主相同。

## 复现

```powershell
dotnet run --project tests/Acceptance/Acceptance.csproj -c Release -- --layout build-check/acceptance-layout.json
dotnet run --project tests/Acceptance/Acceptance.csproj -c Release -- --perf build-check/performance-after.json
```

性能用例需单独运行，避免与其他测试同时占用 CPU。默认创建临时示例库与独立浏览器配置，不连接个人数据库。

同一测试二进制加载旧程序集的方法：复制验收构建输出到独立目录，用改版前同依赖版本的 `Cdiary.dll` 替换副本中的该文件，再运行副本的 `Acceptance.dll --perf ...`。不得覆盖正式发布目录来进行对比。

本次推送包含 A 主窗口改造、设计评审材料、原有回归测试更新和新增验收宿主；正式包仍是此前已经安装的 A 版本。
