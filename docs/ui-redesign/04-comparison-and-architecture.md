# 方案比较与后续架构边界

**后续用户确认优先：现有任务便签不参与重设计。** 三案均保持其完整外观与交互。主窗口主题资源限制在主窗口作用域；不改动任务便签 XAML、全局外观设置及编辑器 CSS。原型中的旧便签设计与相关旧截图已作废。

## 同一套业务，三种组织方式

三案都使用现有任务、日期、笔记、截图和专注能力。不新增项目管理、协作、任务依赖、看板阶段、标签系统、时间段排程或同步服务。原型中的示例时间是固定展示值，不能误读为已接入真实计时。

| 维度 | A 轻岛 | B 纸页 | C 专注台 |
| --- | --- | --- | --- |
| 用户首先看什么 | 今天要做的任务 | 某一天的安排与记录 | 当前工作任务与专注 |
| 全局导航 | 文字侧栏 | 顶部模式，左侧日期 | 顶部工作区标签 |
| 主页结构 | 清单 + 阅读双栏 | 连续日页，阅读按需展开 | 任务 + 阅读 + 专注分栏 |
| 每日备忘 | 次要、可展开 | 日页的主要段落 | 底部摘要或收起区 |
| 任务便签 | 保持现有模式与外观 | 保持现有模式与外观 | 保持现有模式与外观 |
| 主要视觉性格 | 轻快亲和 | 安静、有记录感 | 克制、紧凑 |
| 美观（设计判断） | 4.5 / 5 | 4.5 / 5 | 4 / 5 |
| 可用性（设计判断） | 4.5 / 5 | 4 / 5 | 4.5 / 5 |
| 维护便利，越高越省事 | 4.5 / 5 | 3.5 / 5 | 3 / 5 |
| 现有业务适配 | 5 / 5 | 4 / 5 | 4.5 / 5 |
| 成本相对判断 | 低到中 | 中 | 中到高 |
| 关键风险 | 克制后品牌感不足 | 常用工具进入层级增加 | 深色编辑器与弹层一致性 |

评分是根据现有代码结构和用户偏好作出的专业判断，不是可用性测试成绩或性能基准。不建议把三个导航结构拼在一起；可以在选定结构后吸收其他方案的局部视觉细节。

## 建议选择

A 最符合目前“轻量效率工具、可爱一些、便签简约”的组合要求。B 适合把日记回顾提升为核心场景；C 适合把计时与长时间工作提升为核心场景。三者的最终选型应由实际使用频率决定，而不是仅选择某张截图的配色。

## 选定后的前端边界（未实施）

保留 WPF 主窗口、原生月历与截图列表，保留主窗口 MdXaml 阅读、便签 WebView2 / Vditor 编辑。数据库模型、跨日规则、自动保存协议、提醒调度、截图清理与 FocusService 不因 UI 选型更换。

建议建立一份语义设计值说明，WPF ResourceDictionary 和网页 CSS variables 使用同名角色：Surface、SurfaceRaised、TextPrimary、TextSecondary、Accent、Selected、Success、Progress、Overdue、FocusRing。文字与背景透明度分别处理，背景图片永远不能改变正文透明度。尺寸同时用角色命名，例如 ControlHeight、TaskRowHeight、SectionGap，允许普通窗口和便签使用不同密度。

组件优先沿用当前结构拆分为 WindowChrome、Navigation、TaskRow、TaskStatus、TaskProperties、NoteReading、StickyHeader、FocusControl、ImageTile、InlineFeedback。只有被实际复用的样式才抽出；不在选型前引入新 UI 框架或全面 MVVM 迁移。

可把 MainWindow 中分散的页面可见性整理到单一显示状态，再分页面替换视觉模板。该步骤只在明确实施时执行，并验证返回路径、日期选择、任务选择和窗口生命周期。相同任务在多个窗口中继续共享身份与状态，避免为了新布局构造一套临时业务模型。

动效在原有控件上做短时过渡，不为页面切换重建 WebView2。计时复用现有刷新，截图列表复用虚拟化与缓存。三案都不需要新的常驻浏览器、远程字体或动态背景视频。

## 后续实施顺序与验收

1. 选定方向，确认标准 1100 × 720 和窄屏 760 × 580 的首页样张；任务便签以现状为基线。这一步之后才改生产 UI。
2. 建立语义颜色、字体、间距和基本组件，首先修复对比度与键盘焦点。
3. 落地主页与当日待办布局，保留现有任务便签；回归验证打开便签、任务选择、笔记、完成和跨日状态，确认新主题没有影响便签。
4. 落地月历、专注和截图箱，再统一搜索、完成与设置。
5. 进行 DPI、键盘、IME、长文、异常状态与资源占用对照，再发布。

| 验收方面 | 要求 |
| --- | --- |
| 常用任务 | 添加、修改安排、持续推进、今天收起、继续、完成、恢复均可用；语义不变化 |
| 内容空间 | 标准窗口完整显示至少 5 条普通任务；窄屏至少 4 条。旧任务与备忘不能把主要清单压成一行 |
| 窗口 / DPI | 760 × 580、1100 × 720、1500 × 900、1920 × 1080；100% / 125% / 150% / 200% DPI；标题栏拖动、双击与调整尺寸 |
| 文档 | 主窗口只读，便签直接编辑；Ctrl+B、标题快捷键、目录、表格、图片、IME、保存失败和找回入口 |
| 透明便签 | 背景不透明度与文字分离；深浅桌面、图片、高对比模式；所有图钉可识别 |
| 月历 | 六周月、长标题、大量任务、实际完成日、推进与逾期、选中日完整清单 |
| 专注 | 正计时无完成百分比；番茄进度只代表本轮；暂停、恢复、跨日、隐藏与托盘一致 |
| 截图 | 图片原图、批量选择、到期文字、容量提示、自然日设置；选中与危险操作明确 |
| 反馈 | 读屏与键盘可发现；文本 4.5:1 目标；禁用、处理中、失败、空状态清楚 |
| 性能 | 在同一数据与窗口条件下记录启动、空闲、打开 1 / 3 个便签的内存与 CPU；结果不得在测量前宣称 |

## 本轮原型的使用范围

HTML 原型可切换导航、任务和状态，体验布局与反馈。任务便签入口展示当前控件截图，不再展示新便签方案。系统托盘、系统截图、真实 Markdown 快捷键、真实任务提醒及窗口置顶应在后续 WPF 回归验证中确认未受影响。
